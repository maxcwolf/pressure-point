## Architecture, reviewed 17 October 2026

From a review of the whole repo. The layering already holds (core imports nothing outside itself; render and storage import only core), so these are guardrails and a few risky spots, not a rewrite.

### Now

- [x] **Placement checks that leave the game alone.** `canPlaceItem`, `resizeValid` and `layoutValid` in `src/core/world.ts` try a change on the live game state, rebuild the grid, then undo it and rebuild again, with no `try/finally`: an exception part way leaves a corrupted game for the autosave to write. Restore state in `finally`, then check against a scratch copy of the grid so a check costs no rebuilds. Done in `b9a2da6` and `06ebe57`: `doorValid` had the same pattern and is fixed too; a check now does no rebuilds and takes about 18µs rather than 120 to 170.
- [x] **Saves that replay.** The random seed is a module variable in `src/core/random.ts`, not saved, and `practised` (which followings fade overnight) lives in `SimContext` outside `GameState`, so loading a game changes what happens next. Keep both in the save. Done in `1704937` (save version 31): each game keeps its own random stream, and the once-a-second timer and the noise, warmth and pleasantness grids are saved too. A save is about 17 KB bigger for the grids; run-length coding them would win most of that back.
- [x] **Release versions that match.** Installers take their version from the tag, but the game's `__APP_VERSION__` and the Sentry release come from `package.json`, and nothing checks the two agree. `pages.yml` also deploys the web build on a tag whether the release passed or not. Done in `48c5e4d`: a tag that differs from `package.json` fails the release, and the web build now deploys from the release workflow once the release is published.
- [x] **Cache CI.** None of the nine jobs caches Yarn or the Playwright browsers. Done in `a987e9b`.
- [x] **Lint every layer's boundary.** Only core has an import rule, and its glob misses a third folder level. Add rules for render and storage (core only), and warn when a component imports from `core/sim/*` rather than through `Sim`. Done in `d9a3f37`. A warning for components importing from `core/sim/*` was tried and taken out again: see **Components through `Sim`** below.
- [x] **Electron tidy-ups.** Developer tools and reload are in the production menu, and the full-screen IPC handler doesn't check `senderFrame` as the others do. Done in `2b680dc`. Developer tools can still be opened with the shortcut; `webPreferences.devTools: !app.isPackaged` would close that too.
- [x] **Electron's version.** `scripts/build-desktop.mjs` says it is pinned; `package.json` has `^44.7.0`. Pinned to 44.7.0 in `130f6bc`.

### Soon

- [x] **Route all money through `earn`/`spend`.** Around 16 places in core change `s.money` and the ledger directly (refunds, awards, emergencies, outbreaks, challenges, visits, staffing, cheats), partly because `earn` has no kind for a bonus. Then lint against new ones. Done in `163682a`: 14 places, through `earn(…, 'bonus')`, a new `recoup` for refunds, and `adjustMoney` for the money cheat alone. A lint rule stops new ones, and the chaos test checks the bank against the books.
- [x] **Make autosave cheaper and safer.** Every autosave reads every slot's whole save just to see it exists (`liveEntries` in `src/storage/saves.ts`), and the slot and the index are written without keeping each other right. On desktop, saves live only in Chromium's localStorage: back them up to files in the app's data folder. Done in `512881b`: autosave reads only the list of saves, a failed write leaves the old save and its entry together, and desktop saves are copied to `saved-games/` in the app's data folder and restored from it when localStorage is empty. Thumbnails are not backed up.
- [x] **One set of defaults for new and upgraded games.** `src/core/state/upgrade.ts` repeats about 120 of `newGame()`'s defaults with `??=`, and some disagree (`nextEmergency` is 75 in one, `day + 60` in the other). Done in `1704937`: `startingState()` is the one source for both.
- [x] **A tidier composition root.** `startGame` in `src/app/game.ts` uses `ui` in a callback before it is declared, patches `tools.askToBuy` on after the fact, and decides which overlay to draw from the menu's state. Done: each part is built after what it needs. Rather than being handed `askToBuy`, the tools hand a plot clicked to buy back from `pointerUp`, and the pointer asks; a failed save comes back as a warning for its caller to show; the floor's overlay comes from `HudState.floor`, and a new preview is drawn by the loop before the frame, not from the tools' change callback.
- [x] **A home for `audio.ts` and `voice.ts`.** They sit loose in `src/`, and audio keeps its own localStorage key rather than going through `storage/`. Done: both are in `src/audio/`, which a lint rule lets import only `core`, `storage` and the recordings in `src/sounds/`. The sound and music switches load and save through `storage/settings.ts`, under the key they always had, so a player's choice carries over untouched.

### Later, or as the code is touched

- [ ] **Split `World`** into the grid, pathfinding and the build rules (about 250 lines of them). The build rules are now in `src/core/build-rules.ts` (`3fd17be`), with World passing calls through; the grid and pathfinding are still together.
- [ ] **Gather the balance numbers.** About 150 bare numbers in `staffing.ts`, `guests.ts` and `stations.ts` belong with the others in `src/core/data/`.
- [ ] **Item behavior from data.** 24 `type === 'x'` checks across 15 sim files (`stone_warmer` alone is in six), against the rule that adding an item means adding an entry.
- [ ] **Untangle `staffing.ts`.** Most of the 18 two-way imports inside `src/core/sim/` go through it.
- [ ] **Components through `Sim`, not around it.** The interface reads `sim.s` and `sim.world` directly about 150 times. Not worth a sweep: new and touched code asks `Sim` instead of reading `sim.s`. Components also import about 30 small read-only helpers from `core/sim/*` (`rankName`, `weekday`, `netOf` and the like). That is fine, since every change to the game still goes through `Sim`, and routing them through it would only add pass-throughs; a lint warning for it was dropped as noise. If a hard line is wanted later, draw it between the sim's pure queries and the code that changes state, for example by moving the queries into a module the interface may import, when `sim/` is next reorganized.

## Roadmap

The phases in [roadmap.md](roadmap.md), from the gaps in [two-point-gaps.md](two-point-gaps.md). Its decisions to make were all taken as their defaults, each noted there, but the rival center's, which is left with the rival.

- [x] **Phase 1, taking charge:** policy, chances shown, send home, a queue you can manage, room priority. Two Point's fast-track switch has nothing to do here, since guests already go straight to treatment once diagnosed, so it became calling emergencies first.
- [x] **Phase 2, goals along the way:** staff objectives and year-end awards. Challenges pay money and morale rather than karma: karma is earned once per star and achievement, and a repeatable reward would let a replay farm it.
- [x] **Phase 3, staff careers:** experience and promotions, general qualifications, job assignment, a hiring pool that grows, traits you can see.
- [x] **Phase 4, reading the center:** guest feelings, reviews and reputation in parts, the casebook, overlays. The casebook went in the Stats menu, which now has tabs, rather than the Treatments menu.
- [x] **Phase 5, the business side:** prices per treatment, a retail counter, marketing, house calls.
- [x] **Phase 6, stakes:** a worsening condition, bad vibes cleared with sage, stress outbreaks. Treatment calms a stressed guest as well as a calming session does, and the calming sessions are handed out by clicking, with no one sent to give them.
- [x] **Phase 7, comfort:** calm, fresh linens, temperature and staff needs. Noise and warmth carry like decor does, held back by the walls of each room they pass through. Changing linens is part of a Caretaker's cleaning, and needs a Linen Hamper to take fresh ones from. Staff thirst and hunger only, no toilets: they are seen to between jobs from the guests' own drinks and snacks. Sandbox switches for stress outbreaks (missed in phase 6) and the weather. High Pines comes next.
- [x] **Phase 8, visitors and rivals:** VIPs and the inspector, the center's standing, a rival center. Then The Orchard Estate. VIPs and the inspector are done: the inspector visits every center, not only The Orchard Estate, with a notice five days ahead; VIPs from the first star. The standing and the rival are done: five grades on points for rooms, prestige and staff, kept once reached; ZenMart opens on day 45 at every center, with sales, job offers to staff below 35 morale, and Center of the Year. The Orchard Estate is done too.
- [x] **Phase 9, events:** a mishap per center. Every 80 to 140 days from day 75, announced three days ahead: a power cut at The Exchange and in the sandbox, a storm at The Boardwalk, a big freeze at High Pines (winter only), and wasps at The Orchard Estate; Willow Lane has none. A fire drill anywhere was built, then taken out at Max's request. Each has a price to prepare for it, paid from the notice at the top of the screen. A power cut dims the lights and a storm brings rain. The storm breaks equipment rather than flooding the restrooms as [two-point-gaps.md](two-point-gaps.md) suggested; that is under Next up.
- [x] **Phase 10, building tools:** move and copy rooms, templates, and decorating rooms. Moving is free, and a copy or a room from a template costs what building it would. Templates are kept for every game and export to a file. Decorating is for looks alone, with three floors and three walls free and nine more for karma. Camera rotation and more land moved to Phase 12.
- [ ] **Phase 11, the long game:** machine upgrades, new rooms, regulars, treatment gags, a radio, game settings. Machine upgrades are done: three levels for each piece of treatment equipment, installed by a Caretaker with the Mechanics course. The Recovery Lounge and the Qi Gong Studio are done too, and game settings (keys, edge scrolling, autosave interval), and regulars, with the Shaman's Vision Quest. The treatment machines brought gags of their own in 0.31.0. Left: a second diagnosis room, a radio, and gags for the other techniques, which have only their own way of moving and a few props, such as the cloud in an extraction and the eagle over a vision quest.
- [x] **Phase 12, more building:** camera rotation and more land, put off from Phase 10. More land is done: first as strips from the Money menu's Land tab, then, in 0.27.0, the Two Point way (see Land the Two Point way). Camera rotation is done: a quarter turn at a time with Q and E or a button.
- [x] **The lot sign from behind.** Turned to look from the north, the sign on the front lawn shows its plain back, a teal wedge by the road. Give it a back, or turn it to face the camera. Done: the board is printed on both faces, so it reads the right way round from either side.
- [x] **Difficulty settings.** Presets for a new game (Relaxed, Standard, Demanding) alongside finer settings, the way Two Point's sandbox has them: how many applicants turn up and how often, how often guests arrive and how patient they are, how quickly equipment wears and staff tire, salaries and prices, loan limits, emergency and challenge frequency, and how fast the award bars rise. Done for the sandbox, with eleven settings; "how fast the award bars rise" became how fast reputation grows, and applicants come more or less often rather than in bigger or smaller numbers.
- [ ] **Difficulty, further:** a difficulty per campaign center, and a way to change it in a game under way, from the pause menu.
- [ ] **Way down the line:** a server for community research and other players' institutes as rivals and VIPs.
